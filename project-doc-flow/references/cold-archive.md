# 关账转冷操作

**触发**：新计划或新阶段开始（第0步）；或文档流转门报“热区过程稿超上限”。

## 1. 先回填，后搬运

转冷不等于销账。搬之前逐个过要冷的过程稿：

- 仍生效的决定 → 决策页（带拍板人原话与日期）；
- 没做完、没验证、被 ESCALATE 的事项 → 排期页第2节“已关账包的遗留”或第5节开放事项；
- 现役生产锚（最近一次发布审核）、下一包正在用的合同、长期规格（权限/兼容/运维/教学合同）→ **留在热区**；
- 源码或测试按路径引用的文档 → 留原路径（先 `grep -rn '<热区目录>/' <代码目录>` 查）。

如果排期页里有大段已关账流水，原文搬进冷区 README 的 `readme_extra`（一字不改，链接按新位置重算），热区只留精简状态与遗留清单。

## 2. 写转冷清单（JSON）

按包分组；每组写清完成范围、再读触发词（以后“查什么才读它”）、未结项去向：

```json
{
  "date": "2026-01-31",
  "scope": "1月已关账包的过程稿;不代表质量合格或债务关闭",
  "groups": [
    { "files": ["登录限流-P3-交付-20260120.md", "登录限流-P3-审核-20260121.md"],
      "scope": "发布ACCEPT;登录接口按账号+IP限流",
      "triggers": ["登录限流", "P3"],
      "open_items": "管理端接口未覆盖——排期页§5" }
  ]
}
```

## 3. 跑脚本

```bash
node <skill>/scripts/doc-cold-archive.mjs 清单.json --dry-run   # 看会搬哪些、改哪些入链
node <skill>/scripts/doc-cold-archive.mjs 清单.json             # git mv + 双向改链 + manifest + README,并 git add
node <skill>/scripts/check-doc-flow.mjs                          # 0 ERROR 才算完
```

脚本会拒绝：不在热区根部的文件、有未提交改动的文件、冷区已有同名文件。别的会话未提交的文档只改链接、不替它暂存。

## 4. 核对与收尾

- 用 manifest 逐行核 `source_sha256`（`git show <source_commit>:<old_path>`）与 `cold_sha256`（冷区文件），应全部一致；
- 更新排期页第0节、总路线图“当前状态”、完成台账加一行（过程稿位置填冷区 README）；
- 提交信息写明：转冷篇数、入链改写份数、回填了哪些遗留。
