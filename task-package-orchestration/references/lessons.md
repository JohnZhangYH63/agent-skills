# 跨项目切包约束

在两个以上项目里成立的约束写这里；只和一个项目有关的写该项目 `AGENTS.md` 的「切包约束」节。每条带原因和日期，原因不成立了就删。拆包时把与本包有关的条目原样贴进合同的「适用的切包约束」。

| 日期 | 约束 | 原因 |
|---|---|---|
| 2026-11-10 | base 取 `git fetch` 之后的远端 SHA，不取本地主分支 | 主检出长期落后或与远端分叉时，执行者会在过期代码上实现 |
| 2026-11-10 | worktree 放在仓库目录之外 | 仓库内的 worktree 会被开发服务器的文件监听扫到，拖垮主检出 |
| 2026-11-10 | 项目红线只写在 `AGENTS.md` frontmatter，脚本不带自己的红线数组 | 曾出现正文、配置文件、脚本硬编码三份红线并存，改一处漏两处 |
| 2026-11-10 | 并行的包先跑 `check-disjoint`，共享接口先冻结成合同 | 两个执行者改同一文件，后合并的一方覆盖前一方且无人察觉 |
| 2026-11-11 | 文件域不相交不等于运行态隔离：并行执行或并行跑验收前，端口、Compose 项目、测试库须各自独占；新 worktree 先就绪依赖再跑 `gate-run` | 两个只读审核会话曾共用同一测试库并发跑验收，互相重建库导致假红；空 worktree 缺依赖直接报命令不存在 |
| 2026-11-11 | 审核者的绿灯只对它工具面能看见的部分成立：涉及 UI/运行态却只有构建/CLI 的审核不得签完整 `ACCEPT`；`wide`/`closed` 泳道优先异构模型交叉审 | 曾有 6 包并行 build/tsc/test 全绿，浏览器点三下现三处不可用；同模型自审会漏同源事实错 |
