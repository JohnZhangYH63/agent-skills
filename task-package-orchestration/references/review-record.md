# 审核记录

审核只基于实际产物和证据；执行者的总结只能当索引，不能替代复核。审核者用没看过实现过程的新上下文。

读证据的顺序：确定性检查结果 → 真实 diff 与本次运行日志 → 该类改动以往的返修/回滚记录 → 执行者自述。

```text
任务包：
审核结论：ACCEPT | REWORK_ONCE | ESCALATE
审核者模型与可观察工具面：（`wide`/`closed` 优先与写者异构；列明实际具备的工具面，如仅 CLI / 含浏览器 / 含真机 / 独占运行栈名）

实际 base / worktree / commit：（与合同 base 是否一致）
白名单与泳道检查：（粘贴 check-package-whitelist --max-lane 原始输出）
闸门运行：（粘贴 gate-run 摘要与 gate.json 路径；有基线红时附对照的原始数字）
语义 diff 结论：（改了什么行为；有无合同外语义变化；后端读路径核查：无隐式写/锁、无跨模块循环单查、无超大 limit 内存聚合）
合同验收复跑及原始结果：（审核者自己跑，不抄报告）
运行日志 / 截图 / 真机证据：
合同偏离：
剩余风险与未验证项：

下一步已授权动作：（ACCEPT 本身不授权 merge/push/deploy；closed 泳道另需 owner 授权）
可沉淀的切包约束：（有就写一行，没有写“无”）
```

## 三态判据

- **ACCEPT**：合同内结果和证据全部满足，泳道未超合同上限，且审核者的工具面真实覆盖了验收面（涉及 UI/交互或真实运行态时，无浏览器/真机/真实运行环境的审核者不得仅凭构建与单测绿灯签 `ACCEPT`）。
- **REWORK_ONCE**：合同不变、缺口明确且可一次修正。只给一次；仍不满足 → ESCALATE。
- **ESCALATE**：一次返修仍失败、根因不明、发现隐藏依赖、范围或合同需要变化、泳道超限、触发风险/权限停止条件。新目标、新范围、新验收口径必须开新包。

## 打回包（REWORK_ONCE 时发给原执行者，只发失败的那个单元）

```text
UNIT      包 ID
VERDICT   REWORK_ONCE
REASON    哪条验收没过
EVIDENCE  期望/实际、文件:行、日志路径
SCOPE     只许改的文件；不得动其他单元，不得顺手修旁边的问题
```

没有 SCOPE，被打回的单元会长大：顺手修两处，一个单元的修补变成没人审过的多文件 diff。

## 回传编排者规则（独立子代理 / 独立会话适用）

完整审核记录写进报告或指定审核文件，不在最终回复里重贴已通过的命令长输出：
- **ACCEPT**：只回短回执 `UNIT | VERDICT=ACCEPT | 工具面 | commit | WHITELIST & GATE 计数 | 审核记录路径 | UNVERIFIED（未验证边界/剩余风险，禁省略）`。
- **REWORK_ONCE / ESCALATE**：短回执后直接附上面的五栏打回包或需编排者裁决的最小关键证据（精确 `文件:行`、失败输出片段、合同冲突点），免二次翻找。
