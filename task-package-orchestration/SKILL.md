# 任务包编排

循环住在单元里（做、检查、修、直到绿），图住在单元之间（拆、并行、合并、过闸、打回）。本 skill 管后者，并要求前者的“检查”是程序能判败的。读本 skill 不授予任何权限。

## 0. 项目配置只有一处

- 项目事实只写在仓库根 `AGENTS.md` 顶部的 frontmatter：远端、主分支、验收命令、红线、泳道。字段见 [references/project-config.md](references/project-config.md)。脚本直接解析它；不要在别的文件、脚本或提示里再抄一份。
- 接手任何仓库先跑 `node <skill>/scripts/doctor.mjs`（`<skill>` = 本目录）。没有 frontmatter 就 `doctor.mjs --init` 出草稿：编排者按证据核对后写入，不必等 owner 逐条填。
- 改这份配置的规矩是**不对称**的：收紧（加红线、把路径划进更严的泳道、加验收命令）编排者直接做并在交付里说明；放松（删红线、挪出封死泳道、删验收命令）必须有 owner 的明确同意，写明原话与日期。拿不准的路径按更严的泳道处理。执行者不改这份配置。

## 1. 角色闸

- 角色只来自当前提示和任务授权，不来自模型品牌或能力：`ORCHESTRATOR`（拆包、派包、审包）、`EXECUTOR`（拿冻结合同干活）、`REVIEWER`（独立审核，无修复授权就只报告）。拿不准按 `EXECUTOR`，不得自升。
- `RELEASE_OWNER` 是单独的显式授权：只有被点名者可以 merge、push、deploy、动共享资源。编排者身份本身不带这个权。
- 收到冻结合同即为 EXECUTOR：不重新切包、不派 agent、不扩白名单、不改状态文档、不 merge/push/deploy。

## 2. 先判断拆不拆（默认不拆）

拆分有成本：多份上下文、多次交接、合并风险。**一个窗口装得下、或步骤间强串行依赖，就由一个主循环做完**，闸门照旧。只有下面任一条成立才拆：

1. 装不下：材料加产出超过一个上下文能可靠处理的量。
2. 真独立：至少两块互不读对方的产出、文件域不相交，并行能省时间。
3. 要独立意见：审核、对抗性核查必须用没看过产出过程的新上下文（`wide` / `closed` 泳道优先换异构模型交叉审，防同源盲区）。
4. 泳道不同：一部分落在封死泳道或面广泳道，要和其余部分隔开过闸。

不拆时仍然：先写可判败的验收条件，再动手；做完由新上下文审核，不自己给自己过。
owner 点名「改专项」（单模块/前端直改，免总工）不走本协议，唯一细则见 [references/direct-mode.md](references/direct-mode.md)（2026-11-11 John 同意增设）。

## 3. 画图：单元、依赖、节点

- **单元**：一个可独立验收的结果，一进一出。每包只交付一个。
- **依赖**：只有“下游真的读上游的产出”才算边。说不出跨过去的是哪个文件或接口，就没有边，不该等。
- **切分维度**：按“改错了会波及谁”切，让各单元文件域不相交、各自能独立判败；不按文件夹或工作量平均切。共享接口先冻结成合同，再并行。
- **节点四种**：拆分（编排者，用当前最强模型）、执行（独立上下文，一包一个）、**代码节点**（合并、去重、排序、比对、白名单、泳道——不需要“判断/评估/总结”的转换一律写成脚本，不交给模型）、闸门（审核者 + 脚本）。

扇出前过三道闸：① **先验样板切片**：要扇出的包若共同长在 owner 还没实点确认过的新界面或新骨架上，先由 `FLAGSHIP_DIRECT` 交付首个完整纵切片，经 owner 实点确认并留凭据（原话、日期、截图路径，写进后续各包合同的「依赖」栏）后再扇出，禁凭纸面规格批包；② **地基预埋探针**：已知的一类失败，先在地基包里写成 `check_cmds` 能判败的探针，先于扇出；③ **文件与运行态不相交**：跑 `node <skill>/scripts/check-disjoint.mjs --pkg A=a.txt --pkg B=b.txt`（重叠禁并行），且端口、Docker Compose 项目名、测试库等共享运行槽位各自独占，不共用同一套环境。

## 4. 泳道：按撤回代价开闸，不按自信度

`node <skill>/scripts/lane.mjs --allow-file <白名单>`（派包前）/ `--base <SHA>`（审核时）。

| 泳道 | 是什么 | 过闸要什么 |
|---|---|---|
| `contained` 局部可逆 | 文案、测试、有覆盖的独立函数；错了一次 revert | 白名单机检 + 合同验收 + 审核 ACCEPT |
| `wide` 可逆但面广 | 依赖清单、公共工具、共享 schema、很多调用方共用的东西 | 上面全部 + 全部 `check_cmds` 的原始结果 + 调用方证据 + 独立上下文审核 |
| `closed` 封死 | 迁移、删除、钱账、生产数据、部署 | **不自动过闸**。派包前就要 owner 对这次改动的明确授权和回退路径；ACCEPT 也不放行 merge |
| `redline` 红线 | 任何包都不许改 | 白名单机检恒拒；只有合同写明并传 `--allow-redline <glob>` 才例外 |

封死泳道不是“阈值调得很高”，是不开：阈值会被调松，不开的泳道不会。闸门读证据的顺序：确定性检查结果 → 本次运行的真实 diff 与日志 → 该类改动以往的返修/回滚记录 → 最后才是执行者自述。

## 5. 分级与派工

| 级别 | 什么活 | 谁做 |
|---|---|---|
| `FLAGSHIP_DIRECT` | 产品/架构未定、根因未知、跨模块契约、封死泳道内的改动、首个完整纵切片 | 当前可用的最高能力模型直接做或全程主导（即单主循环） |
| `BOUNDED_EXECUTION` | 目标、范围、行为合同、验证方法都已冻结，可独立验收 | 均衡模型 |
| `MECHANICAL` | 搜索、改名、格式、文档同步、按明确模式补测试 | 低成本模型 |

模型名不写成永久规则；用户当前指令决定人员配置，编排者在派工时指定。派工手段按环境选：同会话子代理（短、边界清楚的包）、独立会话或别的工具的会话（长、owner 可能想中途介入的包）、确定性工作流脚本（大批量扇出，需用户明确要求）。执行者各自独立上下文、各自 worktree（宿主已切入独立 worktree 则直接复用，禁套娃二次创建）；共享上下文的多个执行者会趋同成一个意见。

## 6. 流程

1. **查真实状态（三跳冷启动）**：核当前授权，跑 `doctor.mjs`（有附加 worktree 或脏树补跑 `git-truth-sync/scripts/worktree-audit.mjs`，配了 `doc_*` 跑 `project-doc-flow/scripts/check-doc-flow.mjs`）。进度只走三跳：路线图 → 排期第 0 节 → 现行决策/台账末行；不扫冷区与历史包报告，不把旧对话或“文件存在”当事实。
2. **定拆不拆**（§2），拆的话画依赖、定泳道、跑不相交检查。
3. **冻结合同**：完整按 [references/task-package-contract.md](references/task-package-contract.md) 填。base 一律在 `git fetch <remote>` 之后取远端主分支或列明分支的 SHA（复用宿主原生 worktree 时亦须核对起始点对齐，防默认取错 `origin/HEAD`）；手工建 worktree 放在仓库目录之外（主检出开着 dev 监听时避开仓内的 `.claude/worktrees/`）。验收条件先于实现写好，且程序可判。
4. **派发（空上下文）**：提示自包含，子代理**不 fork 编排者历史**，只传角色、合同路径与必读清单。
5. **非对称回传**：长过程、diff 与通过的命令输出落盘进报告和 `gate.json`，不在回复里重贴：
   - **绿包**：只回结构化短回执（包 ID、commit、白名单与 gate 计数、报告路径、**`UNVERIFIED` 未验证边界**——未验项禁省）。`contained` 凭回执与退出码推进；`wide`/`closed` 或有疑点时下钻读真实 diff。
   - **红包（阻塞 / `REWORK_ONCE` / `ESCALATE`）**：短回执后直接附最小关键证据（失败命令、`文件:行`、期望/实际或分叉点），免二次往返。
6. **过闸**：按 [references/review-record.md](references/review-record.md)。先确认本 worktree 依赖就绪且运行槽位独占，再跑 `check-package-whitelist.mjs --base <SHA> --allow-file … --max-lane <合同泳道>` → `gate-run.mjs [--baseline …]` → 复跑合同验收、看语义 diff。缺浏览器/真机/真实运行环境的审核者不得将构建与单测通过签为 UI 或运行态 `ACCEPT`。审核全文落盘，回传同守第 5 步。
7. **裁决只有三态**：`ACCEPT` / `REWORK_ONCE` / `ESCALATE`。裁决必须改变下一步做什么；不改变下一步的只是报告。
8. **关账**：报告落盘、台账加行、更新唯一下一包（文档流转见 `project-doc-flow`），并做 §8 的学习边。`ACCEPT` 不等于授权 merge/push/deploy——那要 RELEASE_OWNER 单独执行并核对源 SHA、工作树、目标环境与回退。

## 7. 打回：只打回失败的单元

打回包五栏，缺一不发：

```text
UNIT      哪个包
VERDICT   REWORK_ONCE
REASON    哪条验收没过
EVIDENCE  期望/实际、文件:行、日志路径
SCOPE     只许改哪些文件；不得动其他单元，不得顺手修旁边的问题
```

- 四个单元一个红，只打回那一个。整批打回会把三个已经对的重写成“不一样”，再验一遍还可能新挂。
- 返修只一次，合同不变。仍不过 → `ESCALATE`：病根在产生这个单元的计划里，单元内的循环看不见计划。新目标、新范围、新验收口径 = 新包，不伪装成第二轮返修。

## 8. 学习边：验收结论变成切包约束

每次关账、返修或升级后问一句：这是不是下次拆包时就该知道的？是，就写成一条约束（不是抄结果）：

- 只和本项目有关 → 该项目 `AGENTS.md` 的「切包约束」节，一行：`日期 · 约束 · 来源包 · 退场条件`（写明什么前提变化就删）。
- 在第二个项目里又出现 → 升到 [references/lessons.md](references/lessons.md)，并从项目里删掉。
- 约束落在拆包简报里，不塞进某个执行者的指令。没有变成约束的失败会再遇到一次。

## 9. 上下文信噪比

- **真源落盘，不在对话内写滚动摘要**：手写滚动摘要既破前缀缓存，又在宿主自动压缩时二次失真。硬状态（红线、合同、base SHA、`gate.json`、台账、下一包）全在盘上；对话流只传路径、SHA、退出码与 `UNVERIFIED` 边界。
- **压缩后重锚定，不设死轮数停机**：发生宿主压缩或长间隔续接后，从盘上重核 `doctor.mjs`、当前合同/排期第 0 节、最近 `gate.json`/台账末行，不凭记忆背 SHA 或未验项；仅在窗口已被多轮失败日志污染、漏跑机检，或到阶段关账切点时换新会话。
- **单主循环零税负**：不拆包时不套回执模板；基模越强，越多任务留在单主循环完成。

## 10. FALLBACK（旗舰额度不足）

只有用户明确宣布才进入，并写清作用范围。中端模型可临时编排，但不降低验收、红线、泳道或授权标准：缩小任务包、提高证据密度；封死泳道、产品/架构新决策仍需原 owner gate。返修一次仍失败 → 带证据 ESCALATE 给用户。用户明确恢复才退出。

## 11. 底线

- 适用门“无新增红”：基线红给原始数字和对照（`gate-run.mjs --baseline`），不用“基本通过”“应该没问题”。没报错不等于正确。
- 功能正确、内容/模型输出正确、真实可用分开记；测试全绿不替代真实验收。
- 保留首次失败样本与实际成本，不为“全绿”删异常证据。
- 人守在机器判不了、且扇出会放大的地方：扇出前未确认过的新产品形状（实点样板切片，每个新骨架一次），以及最后的不可逆操作（批准合并、上线、封死泳道）。不把人放在图中间逐步确认。
- 结束时核对没有遗留 `git stash`、未清理的临时分支或越界改动。

## 12. 维护本 skill

事件触发，不按日历：

- 每次 `ESCALATE` 或返修后做 §8；跨项目成立的进 `references/lessons.md`。
- 换主力模型后：拿一个以前拆过的任务用单主循环重做，对比结果，据此放宽 §2 的门槛。会随模型变强而过时的只有 §2 和 §5（为“装不下/搞不定”而拆）；闸门、泳道、独立审核、代码节点与信噪比原则和模型强弱正交，不会过时。
- 看三个信号：返修率、升级率、某条泳道连续多包闸门什么都没拦住（说明管得过重，向 owner 提议放松）。
- 每条规则带原因；原因不成立就删。改动走本仓库 git，`node --test tests/*.test.mjs` 全过再提交。字段有不兼容变化时升 `orchestrator_schema` 并在 project-config.md 写升级说明，各项目 `doctor.mjs` 会报出来。
